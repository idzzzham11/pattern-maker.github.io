## Deploying to Vercel

Vercel serves the **pre-built** Flutter web output from the repo root — it does not run `flutter build web` itself. After any code change, you must:

1. `flutter build web --release`
2. Copy built files to repo root:
   ```bash
   cp build/web/main.dart.js .
   cp build/web/flutter_service_worker.js .
   cp build/web/flutter_bootstrap.js .
   cp build/web/flutter.js .
   cp build/web/index.html .
   cp build/web/version.json .
   cp -r build/web/assets/assets/images assets/assets/
   cp build/web/assets/AssetManifest.bin assets/
   cp build/web/assets/AssetManifest.bin.json assets/
   cp build/web/assets/FontManifest.json assets/
   ```
3. Commit and push everything including the copied files.

**Important:** Flutter web serves images from `assets/assets/images/` (not `assets/images/`). The `assets/images/` folder is the source used by the build process; `assets/assets/images/` is what gets served at runtime. Both must be kept in sync.

## Architecture

### 3-Step Flow

The app is a single-flow wizard with `PatternMakerScreen` (`screens/pattern_maker_screen.dart`) managing a `PageView` across 3 steps:

1. **Step 1 – Ukuran** (`widgets/measurement_form.dart`): User picks a fixed size (S/M/L). Tapping a card calls `Measurements.applySize()` which populates all measurement fields from the `SizeChart` lookup table in `pattern_models.dart`.

2. **Step 2 – Style** (`widgets/style_selection.dart`): User selects one option per category (neckline, collar, bodice, sleeve, skirt) from image grids. Data held in `StyleSelections`.

3. **Step 3 – Preview** (`widgets/preview_and_notes.dart`): Tabbed view (Badan, Kolar, Lengan, Skirt) showing step-by-step pattern drafting instructions with images. Instructions are generated by `PatternDraftingInstructions` in `utils/pattern_drafting_instructions.dart`.

### Key Models (`lib/models/pattern_models.dart`)

- `SizeChart` — static lookup table mapping S/M/L to 9 measurements (shoulder, bust, waist, hip, armhole, sleeveLength, frontCenter, backCenter, skirtLength).
- `Measurements` — holds current measurements; `applySize(String size)` fills all fields from `SizeChart`.
- `StyleSelections` — holds 5 selected style strings; `isComplete()` validates all are set.
- `StyleOptions` — static lists of `StyleOption` (name, description, imagePath) for each category.

### Instructions System (`lib/utils/pattern_drafting_instructions.dart`)

`PatternDraftingInstructions` takes a measurements map and styles map and generates `List<PatternStep>` for each section. Each `PatternStep` has a `DiagramType` enum value that maps to an image path.

`preview_and_notes.dart` has two methods that must stay in sync:
- `_getImagePath(DiagramType)` — returns the asset path string for each enum value.
- `_shouldShowDiagram(DiagramType)` — returns true only for types that have a real image. **Both must be updated together** when adding new diagram types.

### Adding New Step Images

1. Add the `.jpg` file to `assets/images/<category>/`
2. Add a new `DiagramType` enum value in `pattern_drafting_instructions.dart`
3. Add the `PatternStep` using that DiagramType in the relevant `get*Steps()` method
4. Add the image path case in `_getImagePath()` in `preview_and_notes.dart`
5. Add the type to `_shouldShowDiagram()` in `preview_and_notes.dart`
6. Rebuild web and copy assets (see Deploying section above)

### Asset Image Conventions

- Thumbnail/overview images (used in style selection grid): `assets/images/<category>/<style_name>.jpg`
- Step-by-step instruction images: `assets/images/<category>/<category>_<stylename>_step_N.jpg`
- Basic pattern steps: `assets/images/<category>/basic_<part>_step_N.jpg`
- All image filenames must be lowercase with no spaces.
